# 战斗格遭遇预览设计

## 1. 设计结论

玩家尝试进入未解决的普通、精英或 Boss 战斗格时，不再立即扣除行动点并切换战斗场景，而是先进入一个可撤销的遭遇预览状态。

预览期间，角色表现上靠近目标格，地图镜头从正视角压低为具有透视感的侧视角，并以 `1.75x` 的默认倍率推近目标格。界面只展示危险度和属性倾向，不展示敌人数量、具体敌人、技能或掉落。

玩家确认后才提交移动、结算行动点与相关触发并进入战斗；取消则播放返回动画，恢复原格和地图镜头，不改变任何局内状态。

## 2. 设计目标

- 强制让玩家在进入战斗前注意到危险度和属性倾向。
- 增强从地图探索进入战斗时的临场感和仪式感。
- 给玩家一次明确的风险确认机会，但不允许借此穿过或免费占据战斗格。
- 保持现有行动点、灾厄、遗物和战斗运行时规则不变。
- 为普通、精英和 Boss 战斗提供统一且可扩展的进入流程。

## 3. 非目标

- 不展示敌人数量或完整敌人编成。
- 不展示敌方技能、精确数值或具体掉落。
- 不允许玩家取消后停留在战斗格或继续穿过该格。
- 不重写现有移动费用、遗物免费或灾厄周期规则。
- 不改变战斗生成、战斗结算或战斗场景内部流程。

## 4. 玩家流程

1. 玩家选择一个相邻且尚未解决的战斗格。
2. 地图输入锁定，角色播放靠近目标格的表现动画。
3. 镜头由地图正视角压低并向目标格推近至 `1.75x`。
4. 目标格成为画面主体，危险度、属性倾向和操作按钮出现。
5. 玩家选择：
   - `进入战斗`：提交移动并进入战斗。
   - `返回`：角色和镜头恢复到预览前状态。
6. 重复查看同一战斗格时使用缩短后的动画。

## 5. 镜头与构图

### 5.1 预览镜头

- 默认推近倍率：`1.75x`。
- 镜头同时执行压低视角和向目标格推近，不只旋转整张地图。
- 目标格约占可用游戏画面的主要部分，是第一视觉焦点。
- 目标格中心略偏向情报面板的反方向，为 UI 留出稳定空间。
- 保留进入方向和少量相邻格边缘作为空间参照，其余地图允许被裁切。
- 角色保持可见，作为焦点和尺度参照。

### 5.2 UI 布局

- 宽屏时，危险度、属性倾向和操作按钮位于右侧。
- 窄屏时，情报与按钮移动到画面底部。
- 情报不放入折叠区或滚动区，无需额外操作即可读取。
- `进入战斗`是唯一高强调主操作，`返回`为低强调次操作。
- 按钮必须显示预计移动费用，不能固定写死为 `1 AP`。

### 5.3 动画时间

- 首次查看某个战斗格：总时长约 `0.7-0.9` 秒。
- 重复查看同一战斗格：约 `0.25-0.35` 秒。
- 推荐顺序：角色靠近 -> 镜头压低并推近 -> 情报和按钮出现。
- 取消时反向播放；确认时镜头继续向目标推进并衔接转场。
- 系统启用减少动态效果时，应缩短或取消大幅镜头运动。

## 6. 信息披露

### 6.1 显示内容

- 危险度：沿用地图现有危险度计算与分级。
- 属性倾向：从目标格已经确定的遭遇数据中提取主要属性。
- 战斗类型：通过普通、精英、Boss 的视觉层级表达，而不是暴露编成。
- 预计行动点费用。
- Boss 钥匙解锁条件或其他不可进入原因。

### 6.2 隐藏内容

- 敌人数量。
- 具体敌人身份和完整编成。
- 敌人技能、生命值和速度等战斗数据。
- 精确掉落和奖励数量。

### 6.3 属性倾向规则

- 最多显示三个主要属性倾向。
- 属性顺序应稳定，不能因重复预览重新随机。
- 没有明显属性倾向时显示“无明显倾向”。
- 属性倾向不使用数量、占比或图标重复次数暗示敌人数量。

## 7. 战斗类型适用范围

普通、精英和 Boss 战斗格全部使用相同的底层预览流程。

- 普通战斗：使用标准危险度与属性表现。
- 精英战斗：提高边框、音效或环境表现等级，但不增加额外情报。
- Boss 战斗：使用更强的镜头和音效表现；钥匙不足时仍允许查看预览，但禁用进入按钮并显示解锁条件。

已解决或已经失去敌对性质的格子不进入战斗预览流程。

## 8. 状态模型

```text
MapReady
  -> PreviewEntering
  -> PreviewReady
     -> Confirm -> CommitMovement -> EnterBattle
     -> Cancel  -> PreviewExiting -> MapReady
```

### 8.1 PreviewEntering

- 锁定地图点击、拖动、缩放和角色移动输入。
- 保存预览前相机状态、角色表现位置和目标格引用。
- 开始角色靠近与镜头推近动画。
- 不修改任何游戏状态。

### 8.2 PreviewReady

- 显示危险度、属性倾向、预计费用和操作按钮。
- 允许确认、返回和系统返回键操作。
- 不允许切换到另一个格子；必须先退出当前预览。

### 8.3 CommitMovement

- 再次校验目标格、相邻关系、行动点、Boss 钥匙和当前流程状态。
- 禁用按钮，保证提交操作幂等。
- 调用现有 `MapMovementService` 提交移动。
- 移动成功后沿用现有节点解析与战斗运行时创建流程。
- 移动失败时不进入战斗，保留预览并显示失败原因。

### 8.4 PreviewExiting

- 隐藏情报和按钮。
- 播放镜头与角色返回动画。
- 恢复预览前地图输入和相机状态。
- 不触发移动、访问、遗物、灾厄或统计事件。

## 9. 行动点、遗物与灾厄

### 9.1 行动点

- 预览阶段不消费或预留行动点。
- 确认时才通过现有移动服务结算实际费用。
- 当前规则中未访问格费用为 `2 AP`、已访问格费用为 `1 AP`，预览按钮应显示对应预计值。
- 若存在概率免除移动费用的遗物，按钮显示基础预计费用，实际结果在提交时结算并反馈。
- 若当前条件完全无法尝试移动，可以查看预览，但进入按钮禁用并显示原因。

### 9.2 遗物

- `OnMoveCostAboutToSpend`、行动点消费和其他移动触发只在确认时执行。
- 取消预览不能消耗次数、推进随机数或产生遗物反馈。
- 同一次确认只能触发一次移动遗物链路。

### 9.3 灾厄

- 预览和取消不改变灾厄状态。
- 若确认移动耗尽当前行动点周期，保持现有敌对格规则：灾厄进入待处理状态，战斗结束并返回地图后再呈现。
- 不在预览层复制或替代现有跨周期支付逻辑。

## 10. 随机性与防滥用

- 预览读取目标格已经确定的遭遇和属性数据，不执行新的遭遇抽取。
- 重复进入预览不能刷新危险度、属性、敌人或奖励。
- 取消不标记格子已访问或已解决。
- 预览次数不进入局内经济统计，除非未来明确需要分析埋点。
- 连续点击、双击或多点触控不能造成重复扣费、重复触发或重复加载场景。

## 11. 建议组件边界

### `MapBattleTilePreviewController`

- 管理预览状态机、输入锁、确认和取消。
- 创建预览上下文并协调镜头、UI 与现有移动流程。
- 不自行计算或扣除行动点。

### `MapBattleTilePreviewView`

- 展示危险度、属性倾向、预计费用、Boss 解锁状态和按钮。
- 只负责表现与用户输入事件，不修改局内状态。

### `MapBattleTilePreviewContext`

- 保存原坐标、目标格、战斗类型、危险度、属性倾向、预计费用和进入资格。
- 保存预览是否为本次会话中的重复查看。

### `MapViewController`

- 提供捕获地图相机状态、进入 `1.75x` 预览镜头和恢复相机的接口。
- 不负责战斗资格、行动点或节点解析。

### `RunGameManager`

- 在敌对格移动入口创建预览，而不是立即提交移动。
- 确认后继续使用既有 `MapMovementService` 和战斗格处理流程。

## 12. 异常与恢复

- 目标格在预览期间失效：禁止确认并退出预览。
- 行动点或钥匙条件在预览期间变化：确认时重新校验并刷新原因。
- 场景加载无法启动：不得留下重复提交入口；保持或恢复可操作的地图状态。
- 应用暂停或失去焦点：保存逻辑位置时仍以原格为准。
- 恢复应用时若无法可靠恢复中间动画，则直接取消预览并恢复地图正视角。
- 教程或其他模态界面出现时，不允许同时进入战斗预览。

## 13. 测试范围

### EditMode

- 状态机合法和非法转换。
- 预览与取消不修改 RunState、行动点和格子状态。
- 预计费用展示覆盖未访问格、已访问格和遗物潜在免费。
- 属性倾向最多三个、顺序稳定且不泄露数量。
- Boss 钥匙不足时允许查看但禁止确认。
- 多次确认只产生一次提交请求。
- 移动提交失败时不创建战斗运行时数据。

### PlayMode

- 普通、精英、Boss 三种战斗格完整预览流程。
- 确认后正确扣费、提交坐标并进入战斗。
- 取消后角色、镜头、UI 和输入恢复。
- 最后行动点进入战斗时，灾厄延迟到返回地图。
- 连点确认、系统返回键、应用暂停恢复和教程阻塞。
- 常用手机宽高比及桌面调试分辨率下无 UI 遮挡。

## 14. 体验验收指标

- 目标格在 `1.75x` 预览中成为第一视觉焦点，仍能辨认进入方向。
- 危险度和属性倾向无需滚动或额外点击即可完整读取。
- 玩家进入战斗前能够复述危险度和至少一个属性倾向。
- 玩家不会误认为取消后可以停留在战斗格或穿过战斗格。
- 重复查看不会因动画过长而明显打断地图规划节奏。
- 相较现有直接进入流程，误入高危险战斗的反馈明显减少。
