## 证据的适用范围

通关路线使用合法命名检查点进行有限分支探索，保留失败分支，局外结算前才能恢复到同代次检查点。最终有效日志只含获胜分支，不含失败分支的额外收益。最后关键回合从真实检查点另由已提交的 Python 策略自动复现。这里证明接口能够按正式规则完成全局闭环，**不宣称示例 demo 从任意开局都能自动通关**。

较早的定向测试包含合成敌群或定向初始能力，用于测试分支和边界；这些不作为正常通关和真实赚点证据。B008b 的 Easy 失败实赚 1 点允许下一局带 AP+1；最终门槛仍由 B008c 的正式 Normal 胜利与真实 11 点完成。实际 UTC 和检查点离线时长保留在日志中，未固定或伪造计分时间。

全量 EditMode 最新基线为 996 项、975 通过、21 失败，失败名称与上一批一致；Python 33 项通过。B008b/c/最终文档批未改引擎或平衡，未重复运行 Unity 全量。既有 PlayMode 失败没有解决，不能报告全部回归绿色。具体失败列表见 B008a 和 README 的历史记录。

当前内容仍有不可用敌群和事件奖励配置缺陷。种子 55 的三处缺少敌群格公开列为 `configurationIssues`，胜利路线避开这些不可用遭遇，未凭空计为清除；幸运迷宫的未配置奖励失败记录见 B005c。它们影响对应内容，接口保留正式错误，不替换简化玩法。所有敌人、武器、遗物和灾厄的任意组合仍未穷举验证。

后端仍需要有授权的团结/Unity 引擎，同宿主一次一个会话；独立 .NET 内核、并行多局和图形体验验证属于后续工作。恢复要求相同版本，不提供旧日志迁移；原子文件/进程中断验证不等于硬件断电或防篡改保证。以上边界不包含在本轮闭环完成声明内。

实际验证产物保存在本机 `outputs/agent-battle` 及隔离工程 Library 内，未加入 Git 的大型输出目录。各批结构化摘要已提交到本目录；最终审计保留证据文件哈希和 Git 批次引用，便于追溯。
